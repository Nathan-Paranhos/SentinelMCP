Entrar no Painel de Governança

Como funciona o ciclo de governança

Quatro passos determinísticos separam descoberta autônoma por IA da autoridade de decisão humana.

01 • DESCOBERTA

Agente descobre e consulta

Codex, Claude ou Cursor executa list_workspaces e query_context antes de editar código, recuperando decisões ativas, incidentes e evidências HTTPS.

02 • PROPOSIÇÃO

Proposta com versão esperada

O agente submete propose_decision ou log_incident com expectedVersion e idempotencyKey. Concorrência e duplicatas são travadas em transação.

03 • REVISÃO HUMANA

Maintainer aprova em /review

Tokens MCP são bloqueados nas rotas web. Somente um revisor humano autenticado (OIDC ou sessão web) com CSRF e papel Maintainer aprova, rejeita ou restaura versões.

04 • AUDITORIA

Comprovantes e Linha do Tempo

Toda consulta grava versões entregues e digest SHA-256 em context_receipts, verificáveis via get_context_receipt ou no inspetor do painel web.

Sem memória compartilhada vs Padrão Sentinel

Transforme histórico disperso em contratos verificáveis entre múltiplos modelos e equipes.

Sem o Sentinel

Divergência & Retrabalho

  • ✕Propostas Recicladas: Agentes sugerem padrões já descartados em PRs antigos.
  • ✕Incidentes Repetidos: Correções ignoram RCAs passados e introduzem regressões.
  • ✕Autoaprovação Insegura: Modelos alteram memória institucional sem revisão humana.
Com o Sentinel-MCP

Governança & Rastreabilidade

  • ✓Busca com Prioridade Técnica: technicalKeys exatas ranqueiam primeiro sobre texto completo PostgreSQL GIN.
  • ✓Separação Estrita MCP/Web: Agentes apenas propõem; humanos decidem com diff da versão vigente.
  • ✓Histórico Reconstituível: Redutores puros reconstroem qualquer versão na timeline e permitem restauração segura.

Engenharia completa e auditável

Construído sobre ASP.NET Core (.NET 9 LTS) e PostgreSQL 16+ com garantias de banco, protocolo e observabilidade.

Protocolo MCP Duplo & STDIO

Suporta POST /mcp (Streamable HTTP stateless para Codex/Claude/Cursor), /mcp/sse autenticado via SDK oficial e modo --stdio nativo sem conflito de porta.

Event Sourcing Imutável

memory_events e memory_payloads são protegidos por triggers append-only no PostgreSQL. Projeções derivam sempre de redutores determinísticos.

Isolamento RLS Forçado

FORCE ROW LEVEL SECURITY com set_config('app.current_workspace_id', ..., true) por transação e papel de menor privilégio sentinel_app.

Concorrência & Idempotência

Locks transacionais por tópico (FOR UPDATE) e lock consultivo por chave de idempotência garantem atomicidade mesmo sob retentativas paralelas.

API Admin & Gestão Visual

Gerencie workspaces, projetos e vínculos (Reader, Contributor, Maintainer) via /api/admin/* ou diretamente na aba Administração do painel.

OpenTelemetry & CSP Estrita

Tracing distribuído, contadores de ferramentas MCP, health/readiness probes (/healthz, /readyz) e CSP sem scripts inline ou CDNs.

Conecte qualquer modelo de IA em segundos

Compatível com OpenAI Codex, Claude Code, Cursor, Gemini CLI e VS Code via Streamable HTTP ou STDIO.

Abrir Console
~/.codex/config.toml & Codex CLI 
# 1) Via Codex CLI (variável de ambiente SENTINEL_MCP_TOKEN):
codex mcp add sentinel --url http://localhost:5000/mcp --bearer-token-env-var SENTINEL_MCP_TOKEN

# 2) Ou direto em ~/.codex/config.toml (ideal para extensão VS Code no Windows):
[mcp_servers.sentinel]
url = "http://localhost:5000/mcp"

[mcp_servers.sentinel.http_headers]
Authorization = "Bearer mock:agent-dev-1|read:memory,write:decision,write:incident|codex"
Claude Code CLI (Streamable HTTP) 
claude mcp add --transport http sentinel http://localhost:5000/mcp \
